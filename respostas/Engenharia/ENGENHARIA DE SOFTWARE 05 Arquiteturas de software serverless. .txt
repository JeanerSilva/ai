ENGENHARIA DE SOFTWARE:: 05 Arquiteturas de software serverless. 
 -
Claro! A arquitetura serverless é um modelo de computação em nuvem onde o provedor de nuvem gerencia a execução do código, alocando dinamicamente os recursos da máquina conforme necessário. Aqui estão cinco arquiteturas de software serverless e os aprendizados mais importantes para cada uma:

### 1. **Funções como Serviço (FaaS)**
- **Aprendizados Importantes:**
  1. **Execução sob demanda:** O código é executado em resposta a eventos específicos, como requisições HTTP ou mudanças em um banco de dados.
  2. **Escalabilidade automática:** O provedor de nuvem gerencia a escalabilidade, aumentando ou diminuindo os recursos conforme necessário.
  3. **Pagamento por uso:** Você paga apenas pelo tempo de execução do código, o que pode reduzir custos significativamente.
  4. **Desenvolvimento focado em lógica de negócio:** Os desenvolvedores podem se concentrar na lógica de negócio sem se preocupar com a infraestrutura subjacente.
  5. **Limitações de tempo de execução:** Funções geralmente têm um tempo máximo de execução, o que pode não ser adequado para tarefas de longa duração.

### 2. **Backend como Serviço (BaaS)**
- **Aprendizados Importantes:**
  1. **Serviços gerenciados:** Inclui serviços como autenticação, banco de dados, armazenamento de arquivos e notificações push.
  2. **Integração fácil:** Facilita a integração com outros serviços e APIs, acelerando o desenvolvimento.
  3. **Redução de complexidade:** Elimina a necessidade de gerenciar servidores e infraestrutura.
  4. **Escalabilidade:** Serviços BaaS são projetados para escalar automaticamente com a demanda.
  5. **Dependência do provedor:** Pode haver um lock-in com o provedor de nuvem, dificultando a migração para outra plataforma.

### 3. **Arquitetura de Microsserviços**
- **Aprendizados Importantes:**
  1. **Desacoplamento:** Cada serviço é independente e pode ser desenvolvido, implantado e escalado separadamente.
  2. **Comunicação via APIs:** Microsserviços se comunicam entre si através de APIs, geralmente usando HTTP/HTTPS.
  3. **Resiliência:** Falhas em um serviço não afetam necessariamente os outros, aumentando a resiliência do sistema.
  4. **Desenvolvimento paralelo:** Equipes podem trabalhar em diferentes microsserviços simultaneamente, acelerando o desenvolvimento.
  5. **Complexidade de gerenciamento:** Aumenta a complexidade de gerenciamento e monitoramento, exigindo ferramentas especializadas.

### 4. **Arquitetura de Eventos**
- **Aprendizados Importantes:**
  1. **Desencadeamento baseado em eventos:** A lógica de negócio é acionada por eventos, como mudanças em um banco de dados ou mensagens em uma fila.
  2. **Desacoplamento:** Componentes do sistema são desacoplados, comunicando-se através de eventos.
  3. **Escalabilidade:** Facilita a escalabilidade, pois cada evento pode ser processado independentemente.
  4. **Flexibilidade:** Permite adicionar novos componentes e funcionalidades sem afetar o sistema existente.
  5. **Complexidade de rastreamento:** Pode ser difícil rastrear o fluxo de eventos e depurar problemas.

### 5. **Arquitetura de API Gateway**
- **Aprendizados Importantes:**
  1. **Ponto único de entrada:** O API Gateway serve como um ponto único de entrada para todas as requisições de clientes.
  2. **Gerenciamento de tráfego:** Facilita o gerenciamento de tráfego, incluindo roteamento, balanceamento de carga e limitação de taxa.
  3. **Segurança:** Implementa autenticação, autorização e outras medidas de segurança.
  4. **Transformação de dados:** Pode transformar requisições e respostas, facilitando a integração com diferentes sistemas.
  5. **Monitoramento e análise:** Fornece monitoramento e análise detalhada do tráfego de API, ajudando na otimização e resolução de problemas.

### 20% Mais Importantes Aprendizados (Regra de Pareto)
Para compreender 80% do necessário sobre arquiteturas serverless, foque nos seguintes aprendizados:

1. **Execução sob demanda e escalabilidade automática (FaaS):** Entenda como o código é executado em resposta a eventos e como a escalabilidade é gerenciada automaticamente.
2. **Pagamento por uso (FaaS):** Compreenda o modelo de custo e como ele pode ser vantajoso.
3. **Serviços gerenciados (BaaS):** Familiarize-se com os serviços comuns oferecidos e como eles podem acelerar o desenvolvimento.
