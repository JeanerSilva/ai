ENGENHARIA DE SOFTWARE:: 04.1 Testes unitários.
 -
Claro, vou te ajudar a entender os aspectos mais importantes sobre testes unitários, que são fundamentais para garantir a qualidade do software. Aqui estão os 20% mais importantes aprendizados que te ajudarão a compreender 80% do assunto:

1. **Definição de Testes Unitários**:
   - Testes unitários são testes automatizados que verificam o comportamento de pequenas unidades de código, como funções ou métodos, de forma isolada.

2. **Objetivo Principal**:
   - Garantir que cada unidade de código funcione corretamente de forma independente, facilitando a detecção de erros e a manutenção do código.

3. **Isolamento**:
   - Testes unitários devem isolar a unidade de código em teste, utilizando mocks ou stubs para substituir dependências externas como bancos de dados ou serviços web.

4. **Automatização**:
   - Testes unitários devem ser automatizados para serem executados rapidamente e frequentemente, idealmente a cada mudança no código.

5. **Repetibilidade**:
   - Testes unitários devem ser repetíveis e produzir os mesmos resultados independentemente do ambiente em que são executados.

6. **Feedback Rápido**:
   - Fornecem feedback rápido sobre a saúde do código, permitindo que os desenvolvedores identifiquem e corrijam problemas rapidamente.

7. **Cobertura de Código**:
   - A cobertura de código é uma métrica que indica a porcentagem do código que é testada pelos testes unitários. Embora alta cobertura seja desejável, a qualidade dos testes é mais importante que a quantidade.

8. **Manutenção de Testes**:
   - Testes unitários devem ser mantidos e atualizados junto com o código de produção. Testes desatualizados podem se tornar um fardo e fornecer falsos negativos ou positivos.

9. **TDD (Test-Driven Development)**:
   - TDD é uma prática onde os testes são escritos antes do código de produção. Isso ajuda a definir claramente o que o código deve fazer e promove um design mais limpo e testável.

10. **Boas Práticas de Escrita**:
    - Testes unitários devem ser pequenos, rápidos, independentes e focados em uma única responsabilidade. Devem ser fáceis de entender e manter.

11. **Nomenclatura Clara**:
    - Os nomes dos testes devem ser descritivos e indicar claramente o que está sendo testado e qual é o comportamento esperado.

12. **Assertivas**:
    - Utilizar assertivas para verificar se o resultado do código em teste é o esperado. Assertivas claras e específicas ajudam a identificar rapidamente o que deu errado.

13. **Ambiente de Teste**:
    - Configurar um ambiente de teste que seja o mais próximo possível do ambiente de produção, mas que permita a execução rápida e isolada dos testes.

14. **Ferramentas e Frameworks**:
    - Utilizar ferramentas e frameworks de testes unitários apropriados para a linguagem de programação em uso, como JUnit para Java, NUnit para .NET, pytest para Python, etc.

15. **Mocking e Stubbing**:
    - Utilizar técnicas de mocking e stubbing para simular dependências externas e focar no comportamento da unidade de código em teste.

16. **Refatoração Segura**:
    - Testes unitários permitem refatorar o código com segurança, garantindo que as mudanças não introduzam novos bugs.

17. **Integração Contínua**:
    - Integrar testes unitários em pipelines de integração contínua para garantir que todos os commits sejam testados automaticamente.

18. **Documentação**:
    - Testes unitários servem como uma forma de documentação viva do comportamento esperado do código, ajudando novos desenvolvedores a entenderem o sistema.

19. **Cobertura de Casos de Borda**:
    - Garantir que os testes unitários cubram não apenas os casos comuns, mas também os casos de borda e situações excepcionais.

20. **Feedback da Equipe**:
    - Encorajar a equipe a revisar e dar feedback sobre os testes unitários para garantir que eles sejam eficazes e mantenham um alto padrão de qualidade.

Com esses aprendizados, você terá uma base sólida para entender e aplicar testes unitários de forma eficaz, garantindo a qualidade e a manutenção do seu código.
