### Protocolo Hypertext Transfer Protocol (HTTP)

#### Origem
O Hypertext Transfer Protocol (HTTP) foi desenvolvido pela primeira vez por Tim Berners-Lee no CERN (Organização Europeia para a Pesquisa Nuclear) em 1989. Ele foi projetado como parte do projeto World Wide Web (WWW) para facilitar a comunicação entre clientes web (navegadores) e servidores web. A primeira versão do HTTP, HTTP/0.9, era extremamente simples e permitia apenas a transferência de arquivos de texto. Desde então, o protocolo evoluiu significativamente, com versões subsequentes introduzindo novos recursos e melhorias de desempenho.

#### Conceitos
HTTP é um protocolo de comunicação baseado em texto que permite a transferência de dados na web. Ele funciona no modelo cliente-servidor, onde o cliente (geralmente um navegador web) envia uma solicitação HTTP para o servidor, que então responde com os dados solicitados. As principais características do HTTP incluem:

- **Sem estado (stateless)**: Cada solicitação é independente e não mantém informações sobre solicitações anteriores.
- **Métodos de solicitação**: Define diferentes métodos para realizar operações, como GET, POST, PUT, DELETE, etc.
- **Códigos de status**: Respostas do servidor incluem códigos de status que indicam o resultado da solicitação (por exemplo, 200 OK, 404 Not Found).
- **Cabeçalhos**: Permitem a transmissão de metadados adicionais entre cliente e servidor.

#### Tipos e Classificações

##### Métodos de Solicitação HTTP
1. **GET**
   - Recupera dados de um servidor.
   - Não deve alterar o estado do servidor.
   - Pode ser armazenado em cache e registrado em histórico.

2. **POST**
   - Envia dados ao servidor para processamento.
   - Pode alterar o estado do servidor.
   - Não é armazenado em cache e não é idempotente.

3. **PUT**
   - Atualiza ou cria um recurso no servidor.
   - Idempotente (múltiplas solicitações têm o mesmo efeito que uma única).

4. **DELETE**
   - Remove um recurso do servidor.
   - Idempotente.

5. **HEAD**
   - Recupera os cabeçalhos de resposta sem o corpo.
   - Útil para verificar a existência de um recurso ou metadados.

6. **OPTIONS**
   - Descreve as opções de comunicação para o recurso de destino.
   - Útil para descobrir métodos suportados pelo servidor.

7. **PATCH**
   - Aplica modificações parciais a um recurso.
   - Não necessariamente idempotente.

8. **TRACE**
   - Ecoa a solicitação recebida para fins de teste e diagnóstico.
   - Pode ser usado para depuração.

##### Códigos de Status HTTP
1. **1xx (Informativo)**
   - **100 Continue**: O cliente deve continuar com a solicitação.
   - **101 Switching Protocols**: O servidor está mudando de protocolo conforme solicitado pelo cliente.

2. **2xx (Sucesso)**
   - **200 OK**: A solicitação foi bem-sucedida.
   - **201 Created**: Um novo recurso foi criado.
   - **204 No Content**: A solicitação foi bem-sucedida, mas não há conteúdo para enviar de volta.

3. **3xx (Redirecionamento)**
   - **301 Moved Permanently**: O recurso foi movido permanentemente para uma nova URL.
   - **302 Found**: O recurso foi encontrado em uma URL diferente temporariamente.
   - **304 Not Modified**: O recurso não foi modificado desde a última solicitação.

4. **4xx (Erro do Cliente)**
   - **400 Bad Request**: A solicitação é inválida.
   - **401 Unauthorized**: Autenticação é necessária.
   - **403 Forbidden**: O servidor recusou a solicitação.
   - **404 Not Found**: O recurso não foi encontrado.

5. **5xx (Erro do Servidor)**
   - **500 Internal Server Error**: O servidor encontrou um erro interno.
   - **502 Bad Gateway**: O servidor recebeu uma resposta inválida de um servidor upstream.
   - **503 Service Unavailable**: O servidor está temporariamente indisponível.

##### Cabeçalhos HTTP
1. **Cabeçalhos de Solicitação**
   - **Host**: Especifica o host e a porta do recurso solicitado.
   - **User-Agent**: Identifica o cliente que está fazendo a solicitação.
   - **Accept**: Especifica os tipos de mídia que o cliente aceita.

2. **Cabeçalhos de Resposta**
   - **Content-Type**: Indica o tipo de mídia do corpo da resposta.
   - **Content-Length**: Especifica o tamanho do corpo da resposta.
