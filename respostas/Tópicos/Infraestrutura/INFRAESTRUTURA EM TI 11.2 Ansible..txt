**Origem do Ansible:**
Ansible é uma ferramenta de automação de TI de código aberto criada por Michael DeHaan em 2012. Foi desenvolvida para simplificar a gestão de configuração, a implementação de aplicações e a orquestração de tarefas complexas em ambientes de TI. Em 2015, a Red Hat adquiriu o Ansible, integrando-o ao seu portfólio de soluções de automação.

**Conceitos do Ansible:**
1. **Automação:** Ansible permite automatizar tarefas repetitivas e complexas, reduzindo o tempo e o esforço necessários para gerenciar infraestruturas de TI.
2. **Idempotência:** As operações realizadas pelo Ansible são idempotentes, o que significa que aplicar o mesmo conjunto de instruções várias vezes não altera o resultado final após a primeira aplicação.
3. **Arquitetura sem agente:** Ansible não requer a instalação de agentes nos nós gerenciados, utilizando SSH para comunicação.
4. **Playbooks:** São arquivos YAML que descrevem a automação de tarefas em uma linguagem declarativa.
5. **Inventário:** Lista de nós gerenciados pelo Ansible, podendo ser estática ou dinâmica.
6. **Módulos:** Unidades de trabalho que realizam tarefas específicas, como instalar pacotes ou copiar arquivos.
7. **Roles:** Conjunto de tarefas, variáveis, arquivos e templates organizados para facilitar a reutilização e a organização de playbooks.

**Tipos e Classificações do Ansible:**

1. **Tipos de Inventário:**
   - **Inventário Estático:** Arquivo de texto simples que lista os hosts e grupos de hosts.
   - **Inventário Dinâmico:** Script ou plugin que gera dinamicamente a lista de hosts a partir de uma fonte externa, como uma API de nuvem.

2. **Tipos de Módulos:**
   - **Módulos de Comando:** Executam comandos específicos no sistema operacional.
   - **Módulos de Arquivo:** Gerenciam arquivos e diretórios.
   - **Módulos de Pacote:** Instalam, removem ou atualizam pacotes de software.
   - **Módulos de Serviço:** Gerenciam serviços do sistema.
   - **Módulos de Usuário e Grupo:** Gerenciam usuários e grupos do sistema.
   - **Módulos de Rede:** Configuram dispositivos de rede.
   - **Módulos de Nuvem:** Interagem com provedores de nuvem como AWS, Azure e Google Cloud.
   - **Módulos de Banco de Dados:** Gerenciam bancos de dados e usuários de banco de dados.
   - **Módulos de Notificação:** Enviam notificações via e-mail, Slack, etc.

3. **Tipos de Playbooks:**
   - **Playbooks Simples:** Contêm uma única play que define uma série de tarefas a serem executadas em um grupo de hosts.
   - **Playbooks Complexos:** Contêm múltiplas plays, cada uma direcionada a diferentes grupos de hosts ou com diferentes objetivos.

4. **Tipos de Roles:**
   - **Roles Básicas:** Contêm apenas tarefas e variáveis.
   - **Roles Completas:** Incluem tarefas, variáveis, handlers, templates, arquivos e metadados.

5. **Tipos de Plugins:**
   - **Plugins de Ação:** Executam ações adicionais durante a execução de tarefas.
   - **Plugins de Callback:** Executam ações em resposta a eventos durante a execução de playbooks.
   - **Plugins de Conexão:** Gerenciam como o Ansible se conecta aos nós gerenciados.
   - **Plugins de Lookup:** Buscam dados de fontes externas.
   - **Plugins de Filtro:** Transformam dados em templates Jinja2.

**Características dos Tipos de Módulos:**

1. **Módulos de Comando:**
   - Executam comandos arbitrários no sistema.
   - Exemplo: `command`, `shell`.

2. **Módulos de Arquivo:**
   - Gerenciam arquivos e diretórios.
   - Exemplo: `copy`, `file`, `template`.

3. **Módulos de Pacote:**
   - Gerenciam pacotes de software.
   - Exemplo: `apt`, `yum`, `pip`.

4. **Módulos de Serviço:**
   - Gerenciam serviços do sistema.
   - Exemplo: `service`, `systemd`.

5. **Módulos de Usuário e Grupo:**
   - Gerenciam contas de usuário e grupos.
   - Exemplo: `user`, `group`.

6. **Módulos de Rede:**
   - Configuram dispositivos de rede.
   - Exemplo: `ios_config`, `net_banner`.
